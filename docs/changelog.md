### 性能优化

- 🚀 **首页滚动顺滑性**：移除逐帧改写全屏 `backdrop-filter` 模糊半径的逻辑。
  旧实现让 Chromium 每个滚动帧都重做一次全屏背景采样 + 高斯模糊，是首页掉帧主因；
  现改为固定模糊半径 + 只调整 `opacity`（合成层操作），并缓存进度值避免重复写 DOM
- 🚀 **首屏离屏即停**：滚过首屏后 Hero 已被不透明内容区完全盖住，此时隐藏 Hero
  并暂停光球动画，长页面后半段不再有额外绘制
- 🚀 **首屏整屏吸附回归（顺滑版）**：v1.2.5 初版改用 CSS `scroll-snap: y proximity` 后吸附
  实际失效——内容区顶部是唯一吸附点、页面顶部 `0` 没有吸附点，`proximity` 几乎不触发；
  换成 `mandatory` 又会把长内容反复拉回内容区顶部。现改为**边界吸附**：只在
  `0 ↔ 内容区顶部` 接管一次滚轮 / 触摸，进入内容区后完全交给原生滚动惯性；解锁用
  `scrollend` + 600ms 兜底（原为固定 800ms 输入锁），已在目标位置时不再接管
- 🚀 **导航栏滚动状态去重**：只在状态真正变化时写 class，不再每帧触发样式重算
- ♿ 补充 `prefers-reduced-motion` 支持：减少动态效果时关闭平滑滚动与光球 / 指示箭头动画，
  吸附改为即时定位（不再关闭吸附）
- 🖼️ 首页文章列表继续使用 `content-visibility: auto` 跳过视口外渲染，图片保持懒加载

## v1.2.4

### 问题修复

- 🐛 **彻底修复首页页脚被 Hero 盖住（v1.2.3 的修复不完整）**：仅取消 main 的
  层叠上下文（`z-index: auto`）不足以让固定 Hero 稳定落在页脚之下。现改为
  **双保险**：
  1. `.hero` 由 `z-index: 0` 改为 `z-index: -1`，作为固定全屏背景沉到根层叠
     上下文的负 z 层，绘制在一切正常内容（含页脚）之下——这是固定背景的规范做法；
  2. 保留首页 main `z-index: auto`（仍是必须项：否则 main 若保持 `z-index: 1`
     会成为层叠上下文，把负 z 的 Hero 困在自己内部、整块仍压在页脚之上）。
  页脚因此始终保持无 z-index 的状态，既不会被 Hero 盖住，也不会回退到早期
  「页脚盖住评论区翻页下拉」的问题。经无头浏览器在真实构建产物上验证：
  滚到页底时 `elementFromPoint` 命中 `footer-inner`，页脚完整可见。

## v1.2.1

### 问题修复

- 🐛 **修复升级后整站没有样式**：Astro 会给 CSS/JS 加内容哈希，升级后旧文件被删除，被缓存的 HTML 仍请求旧文件名，

  一旦配置项未随版本写入（或被 Thymeleaf 整体移除属性）就读取为空，脚本直接跳过；
  同时修复了多种特效在插入节点后随即改写 `transform` / `opacity`，导致浏览器把初态与终态合并、
  transition 完全不触发的问题（表现为点了没反应）

### 补充排查记录：升级后部分页面配色/新样式不生效

上线后收到反馈：更换主题配色后，**首页与瞬间页不跟随**，其他页面正常。经排查
（对比浏览器实际加载的资源、CDP 读取计算样式、比对响应头）确认：

- 浏览器拿到的首页/瞬间 HTML 是 **v1.1.11 / v1.1.12 时期**的旧页面（引用旧哈希 CSS、
  `<html>` 上没有 v1.2.0 新增的 `data-palette` 属性）
- 响应头 `X-Halo-Cache-At` 与 `Cache-Control: max-age=3, s-maxage=120` 表明这些页面
  被 **「页面静态缓存」插件** 缓存，而该插件只随文章变更自动刷新，
  **主题升级 / 主题设置变更不会刷新缓存**
- 裸 `curl`（无浏览器请求头）会绕过该缓存拿到新 HTML，因此服务端"看起来"一切正常

这是缓存层行为、不是主题缺陷，**在 Halo 后台点一次「刷新页面缓存」即可**；
排查步骤已写入 [FAQ](faq.md#升级主题或修改配色后部分页面的新样式配色不生效)。
